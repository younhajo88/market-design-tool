# 홍보이미지디자인툴 Design

## Goal

홍보이미지디자인툴은 관리자가 핸드폰으로 촬영한 과일 사진을 업로드하고, 고정된 템플릿 문구를 얹어 1000 x 1000 WebP 홍보 이미지를 빠르게 만드는 웹앱이다. 결과물은 항상 `.webp` 확장자로 저장된다.

## Users And Platforms

- 주 사용자는 과일 매장 또는 판매 담당 관리자다.
- PC 브라우저와 모바일 브라우저에서 모두 사용할 수 있어야 한다.
- GitHub 저장소 `https://github.com/younhajo88/market-design-tool.git`에 연결하고 Vercel에 배포 가능한 정적 웹앱으로 만든다.
- 서버 저장소나 로그인은 만들지 않는다. 업로드한 이미지는 브라우저 메모리 안에서만 처리한다.

## Recommended Approach

Vite + React + TypeScript 단일 페이지 앱으로 구현한다. 이미지 편집과 합성은 HTML Canvas API를 사용한다. 이 조합은 Vercel 정적 배포가 간단하고, PC/모바일 입력 상태와 캔버스 렌더링 로직을 명확하게 분리하기 좋다.

## Core Workflow

1. 사용자는 홍보이미지디자인툴 페이지에 접속한다.
2. PC에서는 드래그앤드롭 영역 또는 파일 선택으로 이미지를 불러온다.
3. 모바일에서는 파일 선택으로 이미지를 불러온다.
4. 업로드한 이미지는 1000 x 1000 편집 영역에 표시된다.
5. 사용자는 편집 영역 위에서 이미지를 드래그해 과일이 중앙에 오도록 위치를 조정한다.
6. 사용자는 확대/축소 슬라이더로 원본 사진 크기를 조정한다.
7. 사용자는 타이틀, 서브타이틀, 하단 타이틀 문구를 입력한다.
8. 저장 버튼을 누르면 1000 x 1000 WebP 파일이 생성되어 다운로드된다.
9. Web Share API와 파일 공유를 지원하는 모바일 브라우저에서는 공유 버튼도 사용할 수 있다. 지원하지 않으면 다운로드만 제공한다.

## Template

문구 스타일은 한 가지 고정 템플릿으로 제공한다.

- 타이틀: 상단 중앙, 큰 흰색 글자, 진한 파란 외곽선, 검은 그림자
- 서브타이틀: 타이틀 아래 중앙, 흰색 글자, 진한 파란 외곽선, 검은 그림자
- 하단 타이틀: 하단 중앙, 큰 흰색 글자, 진한 파란 외곽선, 검은 그림자
- 사용자는 문구 내용만 수정한다. 글자 색상, 위치, 스타일은 조정하지 않는다.

기본 예시 문구:

- 타이틀: 상품명
- 서브타이틀: 수량 또는 그람 및 가격
- 하단 타이틀: 예약후 당일수령

## UI Layout

첫 화면은 마케팅 랜딩 페이지가 아니라 실제 편집 도구다.

Desktop:

- 좌측 패널: 이미지 업로드, 문구 입력, 확대/축소 슬라이더, 저장/공유 액션
- 중앙 또는 우측: 1000 x 1000 정사각형 미리보기

Mobile:

- 상단: 1000 x 1000 미리보기. 화면 폭에 맞게 축소 표시한다.
- 하단: 업로드, 입력, 확대/축소, 저장 액션
- 드래그 조작은 터치 포인터 이벤트로 동작한다.

## Components

- `ImageUploader`: PC 드래그앤드롭과 파일 선택을 처리한다. 모바일에서는 파일 선택 중심으로 동작한다.
- `PromoCanvas`: 1000 x 1000 가상 캔버스를 렌더링하고, 이미지 위치와 확대/축소, 텍스트 오버레이를 합성한다.
- `TextControls`: 타이틀, 서브타이틀, 하단 타이틀 입력을 관리한다.
- `TransformControls`: 이미지 확대/축소 슬라이더를 관리한다.
- `ExportActions`: WebP 다운로드와 지원 환경의 공유 기능을 제공한다.

## Data Model

```ts
type PromoText = {
  title: string;
  subtitle: string;
  footer: string;
};

type ImageTransform = {
  x: number;
  y: number;
  scale: number;
};

type ExportResult = {
  blob: Blob;
  fileName: string;
  mimeType: 'image/webp';
};
```

## Rendering And Export

- 미리보기는 CSS로 반응형 크기를 적용하되 내부 좌표계는 항상 1000 x 1000을 기준으로 계산한다.
- 업로드 이미지는 원본 비율을 유지한다.
- 업로드 이미지는 원본 파일에서 디코딩한 이미지 객체를 보관하고, 편집 중간에 별도 압축본이나 축소본으로 다시 저장하지 않는다.
- 기본 배치는 이미지가 1000 x 1000 영역을 덮도록 `cover` 방식으로 맞춘다.
- 드래그와 슬라이더 조작은 `ImageTransform`을 갱신한다.
- 저장 시 오프스크린 캔버스 또는 동일 캔버스에서 1000 x 1000 해상도로 다시 렌더링하고 `canvas.toBlob('image/webp', quality)`를 호출한다.
- WebP 품질은 `0.98`로 고정한다.
- 다운로드 파일명은 `market-design-YYYYMMDD-HHmmss.webp` 형식을 사용한다.

## Image Quality Requirements

- 최종 결과물은 항상 1000 x 1000 픽셀 WebP 파일이어야 한다.
- 미리보기 캔버스가 화면에 작게 보이더라도 저장용 렌더링은 별도의 1000 x 1000 기준 캔버스에서 수행한다.
- 이미지 확대/축소와 위치 조정은 원본 이미지 객체에서 매번 다시 렌더링한다. 이전 미리보기 결과를 다시 캔버스에 그려 누적 압축 또는 누적 리샘플링이 생기면 안 된다.
- 캔버스 렌더링 시 `imageSmoothingEnabled`를 켜고 `imageSmoothingQuality`는 `high`로 설정한다.
- 사용자가 이미지를 너무 작게 축소해 1000 x 1000 영역을 덮지 못하는 상태는 허용하지 않는다. 슬라이더의 최소값은 이미지가 편집 영역을 완전히 덮는 배율 이상이어야 한다.
- 원본 사진의 해상도가 1000 x 1000보다 낮은 경우에는 실제 원본 한계 때문에 선명도가 낮을 수 있다. 이 경우 앱은 업로드 후 "원본 사진 해상도가 낮아 결과물이 흐릴 수 있습니다." 경고를 표시한다.
- 텍스트는 저장용 1000 x 1000 캔버스에 직접 그려 외곽선과 그림자가 선명하게 나오도록 한다.

## Error Handling

- 이미지가 아닌 파일을 선택하면 "이미지 파일만 업로드할 수 있습니다." 메시지를 표시한다.
- 이미지를 불러오지 못하면 "이미지를 불러오지 못했습니다. 다른 사진을 선택해주세요." 메시지를 표시한다.
- WebP 내보내기가 실패하면 "이미지 저장에 실패했습니다. 브라우저를 업데이트하거나 다른 브라우저에서 다시 시도해주세요." 메시지를 표시한다.
- 공유 기능이 지원되지 않는 브라우저에서는 공유 버튼을 숨기거나 비활성화하고 다운로드 버튼은 유지한다.

## Testing

- 텍스트 기본값과 입력 상태 업데이트를 테스트한다.
- 이미지 변환 기본값과 `cover` 배치 계산을 테스트한다.
- 슬라이더 최소 배율이 1000 x 1000 영역을 덮는 값보다 작아지지 않는지 테스트한다.
- 드래그 좌표 변환이 표시 크기와 1000 x 1000 좌표계를 올바르게 매핑하는지 테스트한다.
- WebP export 함수가 `image/webp` Blob과 `.webp` 파일명을 생성하는지 테스트한다.
- WebP export 함수가 저장용 캔버스를 1000 x 1000으로 만들고 `imageSmoothingQuality = 'high'`를 적용하는지 테스트한다.
- 주요 사용자 흐름은 브라우저에서 수동 검증한다: 업로드, 드래그, 확대/축소, 문구 입력, WebP 다운로드, 모바일 레이아웃.

## Out Of Scope

- 계정, 로그인, 관리자 권한 관리
- 서버 업로드 또는 이미지 보관
- 여러 템플릿 선택
- 글자 색상, 위치, 폰트, 그림자 커스터마이징
- 배경 제거, AI 이미지 생성, 자동 과일 인식
- 저장된 프로젝트 목록
